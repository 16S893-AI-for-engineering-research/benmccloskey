An Agentic, Verifiable Framework for MEDEVAC Dispatch Modeling

16.S893 Project Proposal

01 · Research question
  • Can an AI agent detect violations of mathematical/operational invariants in MEDEVAC dispatch formulations (MIPs and MDPs)?
  • Can it flag when model behavior deviates from the intended formulation?
02 · The problem
  • Future large disasters can generate casualty demand exceeding available MEDEVAC capacity.
  • Allocating limited evacuation assets across casualties, destinations, and time is a sequential resource-allocation problem.
  • Literature leans towards Markov Decision Processes (MDPs); Mixed Integer Programming (MIPs) formulations are under-explored.
  • Failure mode: not solver failure, but a valid-looking solution that's operationally wrong (i.e. missing exclusivity constraints, reversed inequalities, invalid transitions, omitted rules)
03 · Why it matters
  • Dissertation: MIP + MDP formulations for dispatching limited MEDEVAC assets.
  • LLMs can translate planning problems into optimization formulations, and self-improve via intermediate assessment.
  • Question: Can an agent orchestrate OR tools (invariants, solvers, sensitivity tests) to challenge and verify a model, not just build one?
  • Method: Define invariants, inject known defects, test whether the agent catches them via inspection, solver artifacts, controlled experiments.
  • Payoff: (1) reproducible error-catching during development; (2) perturbation/sensitivity tests separating intent from bugs; (3) solver-grounded evidence for future constraint-level explanations — useful for dev and later auditing.
04 · What the agent should do
  • First: Build/modify constraints; check feasibility, internal consistency, and alignment with intended behavior.
  • Stretch Goal: Add an eXplainable AI (XAI) layer for interpretable explanations of constraints, assumptions, and solution behavior.
  • Stretch Goal: Operations Research-grounded sensitivity + counterfactual analysis on demand.
05 · Data, IP, and export control
  • Data: Open-source or synthetic only. No proprietary lab data on this repo.
  • GitHub: Formulation, agent harness, verification tests, and reproducible experiment configurations.
  • Export Control / ITAR / FOUO / Advisor IP: N/A for the course project.
  • Off-Repo: Proprietary lab data, unpublished PhD extensions, and internal parameters not needed to reproduce the course project.
06 · Where delegation stops
  • Stops at a reported violation. I decide if it's the model, the invariant, or the scenario that's wrong.
  • Agent never silently "fixes" the model.
  • Out of scope this term: replacing the optimizer. Extensions to PhD contributions.
